# dsh-code-security 第一轮迭代

日期：2026-10-12。基于 `91d4d8c770cfaa796d07b7b770a627c3bce8f49e`，本轮版本为 `0.3.8`。此页记录源码迭代和本地验证；发布 CI、npm 完整性及隔离安装结果在发布后独立核验。

这轮先解决增量审查的漏报、范围和证据一致性。原有 37 项测试全部通过，但新增回归测试在旧实现上复现了中文路径、文件级规则等问题被误判为通过。

## 已实现

| 场景 | 原行为 | 当前行为 |
| :-- | :-- | :-- |
| 中文/转义文件名 | Git 引号与八进制路径解析失败，可能返回零发现并通过 | 解码 UTF-8 与 Git 的 C 转义，保留正确文件和行号 |
| 新增私钥、`.env` 敏感项、`audit=false` | 增量扫描跳过文件级规则 | 全量和增量共用匹配，定位实际证据；保留跨行配置检测 |
| 未改动的豁免注释、危险代码 | 缺少上下文，已有 next-line 豁免失效 | 读取少量上下文，只报告证据涉及新增行的问题 |
| 仓库子目录作为会话工作区 | 带入兄弟目录改动，路径基准偏离工作区 | Git 范围和证据路径均相对当前会话工作区 |
| 策略排除 | 增量扫描未应用排除，直接选择文件也绕过排除 | 三种扫描入口统一排除；报告实际扫描和跳过数量 |
| 基线一致性 | 全量的 `./src/a.js` 与增量的 `src/a.js` 指纹不同 | 规范相对路径，并从保存的证据重算旧基线指纹 |
| Git 个性化配置/参数 | 颜色、前缀影响解析；`--quiet` 可误当基线 | 固定输出格式，禁用外部 diff/textconv，校验参数类型 |
| 差异块缺失行 | 接受不完整差异并给出部分结果 | 校验差异块行数，异常时保留原扫描状态并报错 |

主要代码：[diff.ts](../src/diff.ts)、[scanner.ts](../src/scanner.ts)、[tools.ts](../src/tools.ts)、[state.ts](../src/state.ts)。已同步仓库跟踪的 `lib/` 构建产物。

## 兼容注意

未新增依赖；继续沿用项目已有的 MIT 许可与 `proper-lockfile@4.1.2`（MIT），Node 声明保持 `^22.19.0 || >=24.0.0`。原工具名和参数结构保留，增量输出增加明确的扫描/跳过计数。

旧记录的 `./` 前缀兼容已验证。`SEC-303`、`SEC-305`、`SEC-404` 的证据由“整个文件开头”改成“实际匹配片段”；旧基线若使用前一种片段，可能被视为新增。应复扫并人工确认后重新接受，不能自动把新证据全部豁免。

增量检查只涵盖 Git 显示的文本差异，仍不包含未跟踪文件。上下文为前后各 3 行；超出上下文的跨行结构、通用数据流和复杂语言语义未由本轮解决。差异块校验可以发现块内截断，但不代表已解决所有收集上限下的完整性判断。

## 下一轮优先项

以下来自当前代码静态检查，尚未在本轮实现或验收。

1. **扫描完整性门禁。** `scanPath` 遇到不存在目标、读取失败或文件数上限时，应返回明确的完整性状态；`passed` 不能仅因发现为空而为真。还应检查宿主 stdout 收集上限带来的整体截断。
2. **复扫范围校验。** `secure_fix_verify` 应核对上次与本次目标/覆盖范围，避免把没有重新扫描的问题误报为关闭；部分复扫应输出“未验证”。
3. **规则准确性与隐私。** 补充安全/危险样例集，优先处理普通字符串、块注释、已使用安全 Loader 等误报；为密钥证据增加默认脱敏，并设计不依赖明文片段的稳定指纹。
4. **依赖清单解析。** 为标准 `pyproject.toml`、Cargo 依赖区段和损坏清单补测试，再评估采用 MIT/兼容许可的 TOML 解析器；当前 SBOM-lite 不能当作漏洞数据库扫描。

后续功能迭代仍需补单插件真实 DSH 界面验收和更广的跨平台 CI；本版发布验证独立进行。

## Git 行为依据

输出格式、工作区相对范围和外部转换器开关按 [Git diff 官方文档](https://git-scm.com/docs/git-diff) 实现；文件名转义依据 [core.quotePath 官方说明](https://git-scm.com/docs/git-config#Documentation/git-config.txt-corequotePath)。
